# Free test deployment

A live copy for testers that costs nothing: the web app on Cloudflare (Workers static assets, free plan), the API on Render (free web service) and the database on Neon (free Postgres). Not for real teachers: the free API sleeps when idle.

| Part | Service | Config in this repo |
| --- | --- | --- |
| Database | Neon | none, you paste its connection string into Render |
| API | Render (Docker) | `render.yaml` |
| Web | Cloudflare Workers (static assets) | `web/wrangler.jsonc`, `web/public/_headers`, `.github/workflows/deploy-web.yml` |
| Web (old, until Cloudflare is verified) | Azure Static Web Apps | `web/public/staticwebapp.config.json`, same workflow |

Set them up in this order, because each step needs an address from the one before.

## 1. Neon: the database

1. Create a project (any region near Sri Lanka, for example Singapore) with a database named `eduvibe`.
2. On the project dashboard choose **Connect** and turn **Connection pooling off**, then copy the connection string. It looks like `postgresql://user:password@ep-xxxx.region.aws.neon.tech/eduvibe?sslmode=require`. The direct (non-pooled) address is the right one because the API applies migrations on start.

The API accepts this `postgresql://` form as is.

## 2. Render: the API

1. In Render choose **New > Blueprint**, pick this repository and the `main` branch. Render reads `render.yaml` and proposes the `eduvibe-api` web service on the Free plan.
2. Fill in the four values it asks for:
   - `ConnectionStrings__GuruBook`: the Neon string from step 1.
   - `SuperAdmin__Phone` and `SuperAdmin__Password`: the first Super Admin. The password is one-time (you must change it at first sign-in), but the site is public, so use a long random one, not the local `ChangeMe123`.
   - `Cors__AllowedOrigins__0`: the web address from step 3. You do not have it yet, so type `https://placeholder.invalid` and fix it after step 3.
3. Create the service. When the deploy finishes, note the address, for example `https://eduvibe-api.onrender.com`. Opening `/health/ready` there should say `Healthy`.

What happens on first start: migrations create every schema in Neon, then the Super Admin is created from the two values above, once. Later starts find nothing to do. `Jwt__SigningKey` is generated by Render and stays the same between deploys. Render redeploys on its own after every push to `main`. Only code that passed CI can reach `main` (branch protection), so the API that goes live has been tested. If a deploy does not start, open the service in Render, then **Settings > Build & Deploy**, and check that **Auto-Deploy** is **On Commit**; **Manual Deploy > Deploy latest commit** always works.

## 3. Cloudflare: the web app

The app is uploaded as a Worker that only serves files (no Worker code, so the free plan's request limit does not apply to it). `web/wrangler.jsonc` names it `gurubook-web` and turns on single-page routing, so a deep link such as `/classes/12` opens the app. `web/public/_headers` keeps `config.json` and the service worker files uncached.

1. In the Cloudflare dashboard open **Workers & Pages** once. If it asks you to pick a `workers.dev` subdomain, pick one (for example `gurubook`); the site will be `https://gurubook-web.<subdomain>.workers.dev`.
2. Copy your **Account ID** (Workers & Pages overview, right-hand side).
3. Create an API token: **My Profile > API Tokens > Create Token**, template **Edit Cloudflare Workers**, account = yours, zone = all zones (or none). Copy the token; Cloudflare shows it once.
4. In the GitHub repository, under Settings > Secrets and variables > Actions, add:
   - secret `CLOUDFLARE_API_TOKEN`: the token.
   - secret `CLOUDFLARE_ACCOUNT_ID`: the account ID.
   - variable `API_BASE_URL`: the Render address from step 2, without a trailing slash (already there if Azure was set up).
5. Run the workflow **Deploy web (free test)** from the Actions tab (it also runs by itself after CI passes on every push to `main`). Until the secrets and the variable exist the Cloudflare job skips itself. The job log ends with the site address.
6. Go back to Render and add the site address to the allowed origins (see below), then save. Render restarts the API.

### Moving from Azure Static Web Apps

The workflow still deploys to Azure while the secret `AZURE_STATIC_WEB_APPS_API_TOKEN` exists, so both sites work during the move:

1. On Render add `Cors__AllowedOrigins__1` = the Cloudflare address, keeping `Cors__AllowedOrigins__0` = the Azure address. Both sites can now call the API.
2. Try the Cloudflare site: sign in, open a class, reload on a deep link, connect Google Drive.
3. Once it works, make Cloudflare the main address: set `Cors__AllowedOrigins__0` to the Cloudflare address and delete `Cors__AllowedOrigins__1` (the first origin is where Google Drive returns after connecting, unless `Google__WebReturnUrl` is set). Then delete the GitHub secret `AZURE_STATIC_WEB_APPS_API_TOKEN` and the Static Web App in Azure.

Links teachers already shared (self-registration links, the sign-in address in password messages) carry the address they were made on, so share new ones from the Cloudflare site.

Open the site and sign in with the Super Admin phone number and one-time password.

## Things to know

- **Cold start.** Render stops a free service after 15 minutes without traffic. The first request after that takes about a minute while the container starts, and the first sign-in can seem stuck. Tell testers to wait once. Neon also sleeps when idle but wakes in about a second.
- **Limits change.** The free plans' limits are from memory of the plans at the time of writing, so check Render, Neon and Cloudflare when you sign up. Render's free instance has 750 hours a month and Neon's free storage is small, which is fine for testers.
- **Data.** Treat it as test data. Use made-up students, not real children's details.
- **Moving to Azure later.** The API is the same Docker image, so App Service or Container Apps run it unchanged: copy the environment variables from `render.yaml` (and set `ForwardedHeaders__Enabled` the same way). Only the host changes.
- **Other web hosts.** `web/` also has a `Dockerfile` (nginx) for any container host. For anything else, build with `npm run build` and write `config.json` with `apiBaseUrl` next to the output, as the workflow does.

## Settings the API reads

| Variable | Meaning |
| --- | --- |
| `ConnectionStrings__GuruBook` | Postgres, `postgresql://` URI or Npgsql `Host=...;` form |
| `Database__MigrateOnStartup` | `true` applies migrations at start |
| `Jwt__SigningKey` | At least 32 characters, secret |
| `Cors__AllowedOrigins__0` | The web address allowed to call the API (also where Google Drive returns) |
| `Cors__AllowedOrigins__1`, `__2`, ... | More allowed web addresses, for example while moving hosts |
| `SuperAdmin__Phone`, `SuperAdmin__Password` | First Super Admin, created once if none exists |
| `ForwardedHeaders__Enabled` | `true` behind a proxy, so sign-in limits count real client addresses |
| `PORT` | Render's port; the container listens on 8080 |
